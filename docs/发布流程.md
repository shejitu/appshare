# 发布流程

## 一条命令发版

```bash
python tools/publish.py \
  --app-id scrollprompter \
  --name 滚动提示器 \
  --version 1.9 \
  --version-code 19 \
  --apk "E:/我原创的软件/提示器/滚动提示器_v1.9.apk" \
  --notes "修复长文本滚动卡顿"
```

脚本依次做：

1. 校验文件确实是 APK（zip 结构 + 有 AndroidManifest.xml）；
2. 算 `sha256` 和大小；
3. 建 Release（tag = `<appId>-v<version>`，已存在则复用）；
4. 上传 APK 作为 release asset（同名旧资产先删，支持同版本重发）；
5. 写 `<appId>/version.json`，同时写一份 `<appId>/legacy.json`（旧扁平格式，照顾没改解析代码的老客户端）；
6. 更新 `apps.json`、重刷 README 的 App 表格。

先看效果不动手：

```bash
python tools/publish.py ... --dry-run
```

查现在有哪些 App：

```bash
python tools/publish.py --list
```

## 改文档怎么提交

这台机器直连 `github.com` 经常握手失败（`api.github.com` 正常），所以别用 `git push`：

```bash
python tools/sync.py -m "docs: 更新接入说明"
python tools/sync.py --dry-run      # 先看会改什么
```

`sync.py` 走 Git Data API 做一次标准提交（增/改/删都支持），等价于 `git add -A && git commit && git push`。
另外 `publish.py` 发版时会自动把 `version.json` / `apps.json` / `README.md` 同步回本地副本，两边不会打架。

## 参数

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `--app-id` | ✅ | 全小写英文/数字/`-`/`_`，就是仓库里的目录名，**定了别改**（改了等于换新 App，老用户收不到更新） |
| `--name` | ✅ | 显示名称，中文可以 |
| `--version` | ✅ | versionName，如 `1.9` |
| `--version-code` | ✅ | 整数，**必须比上一版大**，客户端靠它判断 |
| `--apk` | ✅ | 本地安装包路径 |
| `--notes` | | 更新说明，`\n` 表示换行 |
| `--notes-file` | | 从 md/txt 读说明，适合长更新日志 |
| `--min-sdk` | | 最低 API，客户端低于此值不提示更新 |
| `--package-name` | | 包名，写进去备案用 |
| `--mandatory` | | 标记强制更新，客户端据此禁用「稍后」 |
| `--mirror` | | 追加下载镜像前缀，可重复 |
| `--token-file` | | PAT 路径，默认 `E:/我原创的软件/github2monthpat.txt`，也可用环境变量 `GH_TOKEN` |
| `--dry-run` | | 只打印不写远端 |

## 新增一个 App

第一次发布时 `--app-id` 填新的值就行，不需要手动建目录、改 JSON，脚本会自动：

- 建 `<appId>/version.json`
- 在 `apps.json` 里加一条
- 在 README 表格里加一行

## 同版本重发（改了包但版本号没变）

直接再跑一次同样的命令。脚本会删掉 Release 里同名资产再上传，并覆盖 `version.json`。
**但客户端可能因为 versionCode 相同而不提示更新**，所以正式修 bug 还是建议涨 versionCode。

## 强制更新

```bash
--mandatory
```

`version.json` 里 `mandatory: true`。客户端应当据此隐藏「稍后再说」，并把 `minSdk` 设成能跑的最低值。

## 回滚到旧版本

Releases 里历史包都在，把上一个版本的 `version.json` 恢复即可：

```bash
# 找到旧提交里的 version.json
git log --oneline -- scrollprompter/version.json
git show <commit>:scrollprompter/version.json > /tmp/old.json
# 手动 PUT 回去，或直接改 Apps.json 里的字段
```

注意：回滚后 `versionCode` 会比用户手机上已装的低，安卓不接受降级安装。
真要回滚，**必须 bump 一个新的更大的 versionCode 重新打包**，不能只改元数据。

## 删除一个 App（下架）

```bash
# 删目录
gh api -X DELETE repos/shejitu/appshare/contents/<appId>/version.json \
  -f message="下架 <appId>" -f sha=<文件sha> -f branch=main

# 再删 apps.json 里对应条目（脚本暂不支持，手工改或用 --list 定位）
```

Release 里的安装包不会自动删，需要的话到 Releases 页面手动删。
